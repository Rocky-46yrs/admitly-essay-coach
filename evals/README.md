# 评测方法
`cases.json` 的 48 个案例全部为合成。E01–E15 原样保留；E16–E30 覆盖新能力及回归风险；E31–E36 针对表达展开及其安全边界。每条 must 为行为验收点，不是自动评分器。

运行 `python3 evals/validate_package.py` 检查必需文件、入口元数据、UI 一致性、相对链接、案例格式和可移植性。运行 `python3 -m unittest discover -s evals -p 'test_*.py'` 验证检查器对损坏包的拒绝能力。结构检查不能证明模型遵守规则。

真实行为测试须由客户端实际加载本地技能执行合成提示，保存最终响应、执行方式和逐项人工判断。多轮案例应延续上下文或显式提供进度账本。自评与人工模拟不得冒充真实模型运行；未运行案例明确标记。E14 在 V0.2 可以先提出路线等待选择，不应为了单轮工作稿而绕过策略规则，继续选择后再验证原有 must。

当前证据见 [RESULTS.md](RESULTS.md)。历史文档在 `v0.1/` 、`v0.2/` 和 `v0.2.1/`，不计入新版结果。禁止将真实用户文书加入测试。

V0.2.1仅对新规则做真实单轮回归，并对先前C04/C05的同一稿件比较旧/新Skill修订。它不是新一轮10案例完整流程盲评，也不是独立留出集；案例及判断均用于开发。结果由本次编辑者核查，不冒充真人盲评。

V0.3.2保留E01–E36原文和口径；新增E37–E48包含足够上下文和anti反例，通过须must满足且anti不出现。导入包E31–E41与本包编号冲突，不直接拼接；依据整合决策重新设计12条而非复制缺上下文案例。
